## Overview
GitHub profile README for Archont561. It points visitors to the portfolio at
https://archont561.github.io/ (source: `Archont561/archont561.github.io`), which is the entry point.
Stack: Bun + EJS, figlet (animated SVG banner), badge-maker + simple-icons (offline badges), and a
citty CLI (`bun run tools <cmd>`, entry `tools/index.ts`) that every hook and workflow calls. No
application code. Registry data comes through clients generated by Hey API (OpenAPI) and gql.tada
(GraphQL). Quality rules come from polyglot-clean-code `v0.1.0` (Pedantic), vendored in `vendor/clean-code-presets/`.

## Commands
`bun run tools <cmd>` is the repository's only automation entrypoint; `bun run tools --help` lists what
is discovered from `tools/commands/*.ts`. `package.json` has exactly one script (`tools`), and there is
no `scripts/` directory. Never invoke Biome, Vale, Alint, ast-grep, knip, dependency-cruiser, secretlint,
actionlint, zizmor, lychee, commitlint, or `bun test` directly in
docs, hooks, or workflows: call the command that wraps them.
- Toolchain: `pixi install --locked` (Bun, actionlint, zizmor, lychee from conda-forge), then `pixi shell`
- Install: `bun install --frozen-lockfile` (lefthook's trusted postinstall installs the git hooks;
  `bun run tools hooks` reinstalls them)
- Capture live facts: `bun run tools capture` (GitHub, npm `@archont561`, PyPI, crates.io and NuGet `Archont561`,
  Maven Central `io.github.archont561`, R-universe `archont561`, prefix.dev `archont561/archont561` +
  `archont561/geospatial` → `data/snapshot.json`; `--print` writes nothing). Accounts live in `data/profile.json`.
- Render: `bun run tools readme` writes `README.md`, `docs/README.md`, `.github/PULL_REQUEST_TEMPLATE.md`,
  `assets/banner.svg` (animated hero banner with embedded Zsh logo and portfolio map), `assets/cards/*.svg`
  (featured project cards, the every-project card), `assets/badges/*.svg`;
  `--check` fails on stale or orphaned output. Both steps: `bun run tools refresh` (`--commit` pushes; used by cron)
- Regenerate typed registry clients: `bun run tools clients` (network; commit the output)
- Lint: `bun run tools lint` (Biome, tsc, ast-grep, Alint, Vale, then maintenance: knip unused files/exports/deps,
  dependency-cruiser layering, secretlint, actionlint and zizmor on workflows; `--only <name>`, `--fix` for Biome)
- Links: `bun run tools links` (lychee over README, AGENTS.md, docs; daily in `refresh.yml`); `--offline` checks
  this repo's own links and anchors and is part of `check`
- Format: `bun run tools format`. Commits: `bun run tools commitlint --message "feat: ..."`
- Test: `bun run tools test` (coverage on, fails under 90% lines or functions)
- Everything CI runs, in order: `bun run tools check` (lint, readme --check, links --offline, test)
- Open a pull request: `bun run tools pr` (lints the title, pushes, `gh pr create` with the rendered template;
  `--title` required for multi-commit branches, `--summary`, `--draft`, `--dry-run`)
- Refresh this file: `bun run tools agents` (preview: `--dry-run`)

## Testing
`bun test` over `tools/tests/` with `@archont561/bun-test-utils`; import `test`, `expect`, `describe`
from `@/tools/tests/fixtures.ts`. Tests mirror the source path: `tools/lib/a/b.ts` →
`tools/tests/lib/a/b.test.ts`, `tools/commands/x.ts` → `tools/tests/commands/x.test.ts` (Alint PCC-R07
fails the build when a pair is missing). Commands are specified as `test.scenario.prop` BDD scenarios
over fast-check inputs (25 examples each; `FC_NUM_RUNS` raises it). Fixtures: `registry` (a `World`
served by `httpMock` behind `networkGuard`; `worldArb(fc)` generates worlds), `repo` (temp root),
`proc` (`runner` spies), `logs`, `exitCode`, plus built-ins such as `tmpdir`, `env`, `stdio`.
Coverage floor is 90% (`bunfig.toml`, `codecov.yml`). A change is done when `bun run tools check`
passes. After touching the banner, look at it in a browser: the reveal plays once with SMIL, then
freezes at the final prompt.

## Project structure
- `tools/index.ts` — citty `runMain`; `tools/lib/cli/discover.ts` finds `tools/commands/*.ts`.
- `tools/commands/<cmd>.ts` — one citty command each: `export default defineCommand({...})`. Thin; logic lives in `tools/lib/`.
- `tools/lib/capture/` — `http.ts` (retrying fetch), `clients.ts` (binds the generated clients),
  `sources.ts` (one function per registry), `snapshot.ts` (drift rule), `codegen.ts` (`clients` command),
  `specs/` (npm, PyPI, NuGet, Maven and R-universe OpenAPI subsets), `clients/` (generated; never hand-edit).
- `tools/lib/render/` — README/docs-index/banner/badge/card builders and output writing (`cards.ts` draws, `showcase.ts` feeds it). `tools/lib/tasks.ts` — capture/render/refresh.
- `tools/lib/quality.ts` — lint/format/test/commitlint/agents plans and the `check` gate.
- `tools/lib/run.ts` — child processes via the spy-able `runner`. `tools/lib/log.ts` — the only output path.
- `tools/lib/config/env.ts` — the only reader of `process.env` (PCC-S06).
- `tools/tests/` — suites mirroring `commands/` and `lib/`; `fixtures.ts`, `setup.ts` (preload).
- `data/profile.json` — curated wording, accounts, badges, `health` badges. `data/snapshot.json` — captured; never hand-edit.
- `templates/profile.ejs` — profile layout and fixed prose. `templates/docs.ejs` — the docs index layout.
  `templates/pr.ejs` — the pull request template (commit types and coverage floor come from config).
  `README.md`, `docs/README.md`, `.github/PULL_REQUEST_TEMPLATE.md`, `assets/` — generated output.
- `docs/<section>/*.md` — setup guide and the rule register. Each needs a `# Title` and a lead
  paragraph: its first sentence becomes the purpose in the generated `docs/README.md`. No CONTRIBUTING.md (personal repository).
- `vendor/clean-code-presets/` — upstream PCC presets, pinned in `UPSTREAM.pin`.
- `.github/workflows/` — `ci.yml`, `pull-request.yml` (commitlint), `refresh.yml` (daily cron). No issue templates.

## Code style & conventions
- Biome formats and lints TypeScript and `data/*.json` (`biome.json`); no `console.*` (use `log`), cognitive complexity ≤ 15.
- Imports: `@/…` from the repository root or `./…` from the same directory. `../` is a Biome error.
- New automation is a new `tools/commands/<name>.ts` plus its scenario test; never a `package.json`
  script, a shell script, a `scripts/` file, a Makefile, or a multi-line workflow `run:`. Alint's
  `tools-single-script` rejects any script other than `"tools": "bun tools/index.ts"`.
- HTTP goes through generated clients; add an operation to the spec or filter in `codegen.ts`, then
  `bun run tools clients`. prefix.dev queries use `graphql(...)` from `clients.ts` so `tsc` checks them.
- Keep the terminal framing: `## \`> command --flag\`` headings, `text`/`diff` fenced blocks.
- Hard-wrap prose at ~90 columns; keep the `<!-- repo-hygiene:* -->` and `<!-- registry:* -->` markers.
- Content goes in `data/profile.json`; structure goes in the template. Do not hardcode facts in the template.
- Images are local SVGs under `assets/`. The one exception is the repo-health footer: the CI, Codecov,
  and refresh status badges are remote because they report live state that a committed SVG cannot.
- Health badge values (Bun version, coverage target, PCC pin) are read from the files that enforce them.
- Colours come from the portfolio's design tokens in tokens.css via data/snapshot.json (paper `#131d18`, forest, sage `#bfd4b8`, copper `#B9794D`).

## Git & PR workflow
Default branch `main`. Remote: https://github.com/Archont561/Archont561. Conventional Commits with
the PCC-R08 types (`feat fix perf docs revert refactor test build ci chore style`), checked by the
commit-msg hook and on every pull request. lefthook runs `lint` + `readme --check` before a commit and
`check` before a push. PR titles become squash commits, so they are linted twice: by `bun run tools pr`
before opening, and by `pull-request.yml` on every open, edit, and push (Alint `pr-title-linted` and
`pr-title-edited-trigger` keep that step and its `edited` trigger in place). Open pull requests with `bun run tools pr`, never `gh pr create` by hand, so the body
is the rendered template. The PR template exists only as `.github/PULL_REQUEST_TEMPLATE.md` rendered from
`templates/pr.ejs`: change the checklist in the `.ejs`, run `bun run tools readme`; Alint rejects a missing
generated header, a missing `templates/pr.ejs`, or a template in any other GitHub location.
Commit generated files (`README.md`, `docs/README.md`, the PR template, `assets/`) with the change that produced them, and commit `bun.lock`.
Workflows use read-only `contents` by default and actions pinned to full commit SHAs.

## Gotchas & hard-won lessons
- `<%= %>` HTML-escapes (`"` becomes `&#34;`); use `<%- %>` for raw strings with quotes.
- `<% %>` emits nothing: `<% arr.join() %>` silently renders empty (this once produced `focus: []`).
- GitHub shows README SVGs via `<img>`: no JavaScript, no external fonts. Animate with SMIL/CSS only.
- Block glyphs drawn as `<text>` show seams; the banner draws `█` as rects and `╔═╗║╚╝` as paths.
- Reduced-motion overrides of SMIL need `!important`. Playwright's reducedMotion does not reach `<img>`
  documents; open the SVG directly to test it.
- Some simple-icons (e.g. githubpages) are too wide to read at badge size; simple-icons has no Vale logo.
- badge-maker rejects `logoBase64: undefined`; omit the key instead.
- Bun blocks postinstall scripts: Alint, Vale, and ast-grep download binaries, and lefthook installs the git
  hooks, so all four are in `trustedDependencies` (Alint checks lefthook stays there).
- `bun test` alone does not put `node_modules/.bin` on PATH, and Bun's spawn ignores PATH changes at runtime.
- Alint JSONPath needs bracket notation for dashed keys: `$.rules['type-enum']`.
- The portfolio is served from the domain root; old `archont561.github.io/Archont561/...` links are 404.
- PyPI user pages and npmjs.com sit behind bot challenges: use PyPI XML-RPC `user_packages` and
  `registry.npmjs.org/-/org/archont561/package`, not HTML scraping.
- prefix.dev GraphQL wants `archont561/archont561`; the web page is `/channels/@archont561/archont561`.
- Only `0.0.0` or placeholder releases are reserved; Conda `0.0.0.devYYYYMMDD` builds are real. An R-universe
  package registered in `Archont561/archont561.r-universe.dev` but not built yet is reserved too.
- NuGet search and Maven POMs live on other hosts than their clients' base URL: pass `baseUrl`
  (`BASE_URLS.nugetSearch`, `BASE_URLS.mavenRepo`, `universeUrl(name)`); Hey API ignores path-level `servers`.
- Maven: search `central.sonatype.com/solrsearch` (search.maven.org misses Portal-published artifacts);
  the Central Portal API sits behind Cloudflare. An R-universe with no build answers 404 on `/api/packages`.
- Hey API needs the TypeScript 5–6 JS compiler API; TypeScript 7 (native) has none, so `typescript` stays on 6.
- bun-test-utils' `httpMock` tries handlers newest-first and lets unmatched requests reach the network;
  the `registry` fixture arms `networkGuard` first and answers everything with a route or 404.
- `test.scenario.prop` exposes no fast-check options; the sample count is set in `tools/tests/setup.ts`.
  In plain `test()` bodies, import `expect`; only scenario steps receive it in the context.
- Bun ignores `process.exitCode = undefined`; reset it to `0` (the `exitCode` fixture does).
- Do not name generated scenario values after fixtures (`page`, `snapshot`, `env`, `seed`, ...).
- Adding or renaming a doc or a command changes `docs/README.md`; run `bun run tools readme` or `readme --check` fails.
- actionlint, zizmor and lychee ship no npm package: Pixi installs them (and Bun) from conda-forge.
  `tools/lib/toolchain.ts` prefers `.pixi/envs/default/bin`, then PATH, so hooks work outside `pixi shell`.
  `pixi.toml` must stay task-free (Alint `pixi-no-tasks`); its `bun` pin equals `packageManager` (a test).
  Renovate (`renovate.json`, the only update bot) bumps `pixi.toml` + `pixi.lock`, `bun.lock` and action
  digests after a 7-day release age. It never touches `packageManager`: conda-forge trails Bun upstream,
  so when a Pixi PR moves Bun, set `packageManager` to the same version in that PR.
- dependency-cruiser needs Node 22+; it runs as `bun run --bun depcruise`. Its rules in
  `.dependency-cruiser.json` are the layering: lib never imports commands or tests, commands never import each
  other, only `capture/sources.ts` and `capture/clients.ts` touch the generated clients, no cycles, no orphans.
- knip cannot see CLIs spawned from string arrays: `knip.json` `ignoreDependencies` must equal
  `CLI_PACKAGES` in `quality.ts` (plus secretlint presets, minus typescript); a test enforces it.
- lychee remaps `github.com/Archont561/Archont561/{blob,tree}/main/…` and workflow badge URLs to the working
  tree, so self-links are checked before a push; npmjs.com pages are excluded (403 to bots).
- Alint's YAML JSONPath cannot address a workflow's `on:` key (YAML 1.1 reads it as boolean `true`);
  check triggers with `file_content_matches` instead.
- README order: figlet banner (with embedded Zsh logo and portfolio map) → nav badges → `ls --principles`
  plain list → `ls --infrastructure` cards → contribution log →
  FAQ (`<details name="faq">`, one open at a time) → connect badges.
  Verbose sections belong in the FAQ, not above it.
- Project cards: `featured: true` in `data/profile.json` picks them, in file order. Stack chips are the repo's
  GitHub primary language and registry chips the registries with a real release (`shipsTo`), both from
  `data/snapshot.json`; never hand-write them. A retired card becomes an orphan and `readme` removes it.
- Card motion cannot react to hover or scrolling (an `<img>` gets neither): the spotlight tours the grid and
  the terminal replays; both stop under `prefers-reduced-motion`.
- `curl` needs `--compressed` for `https://crates.io/api/openapi.json`.

## Security & secrets
No secrets are required. `capture` uses `GITHUB_TOKEN`/`GH_TOKEN` only if set, to raise the GitHub
rate limit. Codecov uploads use OIDC (`id-token: write` on the test job only), so there is no
`CODECOV_TOKEN`. Only `refresh.yml` gets `contents: write`. Never commit real secrets. The profile
publishes only public facts about code: no name, location, employer, availability, or contact details.

## Boundaries
- ✅ **Always**: run `bun run tools check` before pushing; add the paired test for every new module; edit `data/`, `templates/`, `tools/`.
- ⚠️ **Ask first**: adding dependencies, adding a second automation entrypoint, adding or loosening workflows, changing profile wording or claims, adding a rule deviation.
- 🚫 **Never**: add `package.json` scripts beyond `tools` or automation outside `bun run tools`; edit `vendor/` (override locally and record it in `docs/concepts/rule-register.md`); hand-edit `README.md`, `docs/README.md`, `.github/PULL_REQUEST_TEMPLATE.md`, `assets/`, or `tools/lib/capture/clients/`; add issue templates (dev-only repository) or pull request templates outside `templates/pr.ejs`; embed remote images outside the health footer; lower the 90% floor; commit secrets; fabricate personal details or metrics; force-push `main`.
